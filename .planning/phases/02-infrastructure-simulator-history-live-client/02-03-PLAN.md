  <action>
  Boot queries: `bot` (small), own `bot_credential` row (resolve myBotId from identity; verify SQL literal syntax for identity), `match_participant WHERE bot_id = ME`, `open_lobbies`, `open_lobby_members`, `my_rack`, `tournament`, `tournament_entry WHERE bot_id = ME`. Per match M (on first participant row of a match not yet tracked): `match_state WHERE id = M`, `match_participant WHERE match_id = M`, `auction WHERE match_id = M`, `auction_result WHERE match_id = M`, `word_play WHERE match_id = M`, `tournament_match WHERE match_id = M`; unsubscribe after the match ends and its log is flushed. Also probe whether range predicates work (`auction WHERE match_id > X`) and record the result in SUMMARY (do not depend on it).
  Session/adapter: one MatchDriver per running match. Build MatchConfig (players in match_participant id order with names/isSim/simStrategy from `bot`; auctionType; auctionDurationMs; startingRackSize; totalAuctions = 98 − rack·P; kind from tournament_match phase else 'lobby'). myStartRack from my_rack rows of M at start (or reconstructed: current rack + played − won on resume). Batch each server transaction's callbacks and process once (setImmediate/queueMicrotask) in this order: results → words (dedupe by word_play row id) → balances (setBalance) → my_rack (setMyRack) → new auction open (remainingAfter = match_state.bag_total). Record every applied event with the src/state MatchEvent format to the match log.
  Decision loop per auction open: (1) anchor: policy.decide(view, auction, {budgetMs: 15}) → submit its words (in order, with a local reservation multiset so in-flight words never double-spend letters; release on settle) then submitBid; (2) refine: if time remains before the deadline, decide again with budgetMs = clock.budgetFor(...) and resubmit the bid only if it changed (bid 0 withdraws), plus any new words. Never submit after the deadline. Run policy decide synchronously but measure event-loop lag; record decide ms.
  Final auction (bag_total == 0): call decide immediately (policies flush there); submit words first; then bid. On any word rejection, refresh rack from my_rack and re-plan once; log all rejections with server error text.
  Lifecycle: joinLobby when not in a Running match, not held for a tournament and not NO_LADDER; rejoin after Ended (respect MAX_MATCHES); TOURNAMENT_ID registration ('auto' registers for any tournament in Registration status once); handle "already in a running match"/tournament refusals quietly.
  Tests (no network): a fake connection/table harness that replays a recorded or synthetic transaction stream into the adapter and asserts tracker state, batching order, dedupe, reservation logic, deadline gating, final flush.
