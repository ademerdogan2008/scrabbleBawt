# Architecture Research — scrabbleBawt

**Author:** orchestrator (architect). **Status:** binding for all build phases; changes require an explicit decision logged in PROJECT.md.

## Principles

1. **One brain, two bodies.** The exact same `Policy` code runs inside the fast simulator and inside the live SpacetimeDB client. The live client is a thin adapter: SpacetimeDB rows → `MatchTracker` events → `Policy.decide()` → reducer calls. Anything we measure in simulation is what we ship.
2. **Pure deterministic core.** `core/`, `engine/`, `state/`, `bots/` are pure TypeScript with no I/O and no `Math.random()`; all randomness comes from an injected seeded `Rng`. Same seed ⇒ same match.
3. **Performance first in the engine.** Typed arrays, precomputed dictionary indices, anagram-class trie, memoized packing. Decisions must fit a ~250 ms budget per 1 s auction (live latency eats the rest).
4. **Everything measurable.** Every match can emit a trace (bids, prices, words, timings) for loss analysis; every tunable lives in one JSON-serializable params object.
5. **Strict directory ownership** so parallel agents never edit the same files (see Ownership table).

## Core types (binding signatures — `src/core/types.ts`)

```ts
export type PlayerId = number;                    // bot_id (u64 server-side, < 2^53 in practice)
export type AuctionType = 'Vickrey' | 'FirstPrice';
export type SimStrategy = 'Cheapskate' | 'ValueBidder' | 'Aggressive' | 'Human';

export interface PlayerInfo { id: PlayerId; name: string; isSim: boolean; simStrategy?: SimStrategy; }

export interface MatchConfig {
  matchId: number;
  auctionType: AuctionType;
  auctionDurationMs: number;     // default 1000 (range 250..10000)
  startingRackSize: number;      // default 5 (range 0..20)
  startingBalance: number;       // 100
  players: PlayerInfo[];         // match_participant order
  myId: PlayerId;
  totalAuctions: number;         // 98 - startingRackSize * players.length
}

export interface AuctionInfo {
  auctionId: number;
  index: number;                 // 0-based (= match_state.current_round - 1)
  letter: string;                // 'A'..'Z'
  opensAtMs: number;             // server clock
  closesAtMs: number;            // server clock
  remainingAfter: number;        // match_state.bag_total while open; 0 ⇒ LAST auction (its letter is unusable)
}

export interface AuctionOutcome { auctionId: number; index: number; letter: string; winnerId: PlayerId | null; paid: number; }
export interface WordPlayEvent { playerId: PlayerId; word: string; reward: number; auctionIndex: number; }

export interface Decision {
  words: string[];               // submitted in order BEFORE the bid; each playable sequentially from the rack
  bid: number;                   // integer >= 0 (0 = no bid); <= balance after the words' rewards
}

export interface DecideContext { budgetMs: number; rng: Rng; now(): number; }

export interface Policy {
  readonly name: string;
  onMatchStart(view: MatchView): void;
  decide(view: MatchView, auction: AuctionInfo, ctx: DecideContext): Decision;
  onAuctionClosed?(view: MatchView, outcome: AuctionOutcome): void;
  onMatchEnd?(view: MatchView): void;
}
export type PolicyFactory = (seed: number, opts?: Record<string, unknown>) => Policy;
```

`decide()` must be callable more than once per auction (live anytime re-bid: a quick call with a tiny budget, then a refined call); it must not double-count words already submitted (the tracker reflects them).

## MatchView (`src/state/view.ts`)

```ts
export interface PlayerState {
  info: PlayerInfo; balance: number; score: number;
  won: Rack;              // letters won at auction (cumulative)
  played: Rack;           // letters used in this player's words (cumulative)
  revealedHidden: Rack;   // letters proven to come from hidden starting tiles (played beyond won)
  knownHeld: Rack;        // won + revealedHidden - played  (lower bound on current rack)
  hiddenUnknown: number;  // startingRackSize - total(revealedHidden)
  lettersWon: number; totalPaid: number; words: WordPlayEvent[];
}
export interface MatchView {
  config: MatchConfig;
  me: PlayerState & { rack: Rack; startRack: Rack };   // exact for me
  players: ReadonlyMap<PlayerId, PlayerState>;
  opponents: readonly PlayerState[];
  history: readonly AuctionOutcome[];
  words: readonly WordPlayEvent[];
  auctionsDone: number;          // closed auctions
  auctionsRemaining: number;     // including the open one
  unseen: Rack;                  // BAG - my start - every auctioned letter (incl. open) - Σ opp revealedHidden
  current?: AuctionInfo;
}
```

`MatchTracker` events: `start(config, myStartRack)`, `auctionOpen(info)`, `auctionResult(outcome)`, `wordPlay(ev)`, `balances(id, balance, score)`, `myRack(rack)` (live consistency check). Sim and live feed identical event streams.

## Simulator semantics (must mirror server; details in RULES.md)

1. Bag = standard 98 counts. Deal `startingRackSize` tiles to each player in seat order via `drawLetter` (uniform index over alphabetically sorted remaining counts).
2. Draw the first letter → auction 0 opens. **Sims bid at open** (strategy base + jitter∈[-2,2], max(·,1), min(·,balance), skip if ≤0).
3. Every Policy seat gets `decide(view, auction, ctx)` on the state at open (simultaneous move). Apply all returned words (validity + rack + reward to balance & score, publicly visible), then bids (reject bid > balance).
4. Close: keep bids > 0, shuffle (rng), stable sort desc; winner = first; Vickrey pays `second ?? min(1, first)`; FirstPrice pays `first`; deduct only if balance ≥ paid; add letter. Record outcome (top bid kept only in trace).
5. If a sim won: it plays `findBestPlayable(rack, 3)` (length desc, lex asc) — one word.
6. Draw next letter; if bag empty ⇒ match ends immediately (the last letter is unusable for policies). Rank by score; ties share place.

## Live adapter rules

- Subscribe narrowly: own `bot`/credential rows, `match_participant WHERE bot_id = me` (detect new match), then per match `match_state WHERE id=M`, `auction|auction_result|word_play|match_participant WHERE match_id=M`, `my_rack`, and `bot` rows of opponents. Never `subscribeToAllTables` (history is 1.7M+ rows).
- Process each server transaction fully before deciding (batch callbacks, decide in a microtask/setImmediate).
- On auction open: quick decision (≤20 ms budget) → submit; refined decision (budget = time-to-close − safety − measured submit latency) → resubmit bid if different. Words before bids.
- On the LAST auction (remainingAfter=0) and on the one before it: flush all remaining words immediately; verify via word_play echo; retry rejects.
- Reconnect with token; rebuild tracker from per-match history rows; rejoin lobby after `Ended`.
